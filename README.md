# html-inject-scan (C++)

Консольное приложение на C++ для **автоматизированного поиска отражённых HTML-инъекций**
(reflected HTML injection / XSS) в веб-приложениях. Принимает список URL, обнаруживает
параметры из нескольких источников, подставляет в них payload и проверяет, отражается ли
заданный маркер в ответе сервера. Поддерживает авторизованные сессии через пользовательские
HTTP-заголовки и cookie.

Это переписанная на C++ версия Python-инструмента `html-inject-scan` с двумя ключевыми
улучшениями: **умной отправкой запросов** (батчинг параметров с поиском уязвимых через
бинарное деление) и **тихим режимом** вывода только находок.

## Назначение

Инструмент помогает специалисту по безопасности (или разработчику) быстро проверить набор
URL на наличие отражённых инъекций: ситуаций, когда переданное в параметре значение без
должной фильтрации попадает в HTML-ответ и потенциально позволяет внедрить разметку или
скрипт. Программа не эксплуатирует уязвимость, а лишь сигнализирует об **отражении маркера**,
что является первичным признаком потенциальной XSS/HTML-инъекции.

## Возможности

- Сбор имён параметров из 4 источников (см. ниже).
- Интерактивный или автоматический (`--auto`) выбор параметров для тестирования.
- Подстановка произвольного payload (`-p`) и поиск произвольного маркера (`-m`).
- Авторизованные сессии: пользовательские заголовки (`--header`), cookie (`--cookie`).
- Работа через прокси (`--proxy`), например через Burp Suite.
- HTTP-методы GET и POST (`--method`).
- **Умная отправка**: батчинг параметров под лимит длины URL (`--max-url-len`) и поиск
  уязвимых бинарным делением — резко меньше запросов, чем один запрос на параметр.
- **Тихий режим** (`-s`): печатать только находки.
- Параллельное сканирование нескольких URL (`--threads`, вместе с `--auto`).
- Сохранение находок в TSV-файл (`-o`).

## Источники параметров

| Источник | Описание |
|----------|----------|
| **URL query** | Параметры из query string URL (`?id=1&type=osago` → `id`, `type`) |
| **HTML page** | Атрибуты `name=` со страницы (только `<input>` или все теги, `--mode`) |
| **Wordlist** | Пользовательский файл со списком параметров (`-w params.txt`) |
| **Extra/builtin** | Встроенный набор + пользовательские через `--extra` |

## Как это работает

### Умная отправка (батчинг + бинарное деление)

Вместо одного запроса на каждый параметр маркер подставляется сразу в несколько параметров,
а длина собранного (уже URL-кодированного) URL не превышает `--max-url-len` (по умолчанию
2000). Если в ответе маркер не найден — весь батч считается чистым за один запрос. Если найден
— батч делится пополам и рекурсивно сужается, пока не выделятся конкретные отражающие
параметры. Это даёт логарифмическое число дополнительных запросов вместо линейного.

```
[ a b c d e f g h ]  один запрос, маркер отразился
        │ делим пополам
   ┌────┴────┐
[ a b c d ]   [ e f g h ]   по запросу на половину
   │ не отразила   │ отразила → делим дальше ...
```

### Проверка отражения

Для набора параметров строится тестовый URL с payload, отправляется запрос, и в теле ответа
ищется маркер (подстрока). Маркер должен быть достаточно уникальным, чтобы не встречаться на
странице случайно (по умолчанию `<zxcasd>`).

## Установка и сборка

Требуется компилятор C++17 и CMake ≥ 3.16. Сторонние библиотеки (`cpr` для HTTP и `doctest`
для тестов) подтягиваются и собираются автоматически через CMake `FetchContent` — отдельная
установка не нужна.

```bash
cmake -B build
cmake --build build
```

Исполняемый файл: `build/html-inject-scan`.

## Запуск тестов

```bash
ctest --test-dir build
```

## Быстрый старт

```bash
# Один URL — интерактивный выбор параметров по каждому источнику
./build/html-inject-scan -u "https://target.com/page?id=1"

# Список URL из файла, автоматический выбор всех параметров
./build/html-inject-scan -l urls.txt --auto
```

## Сценарии использования

### Автоматический режим с сохранением результата

```bash
./build/html-inject-scan -l urls.txt --auto -o reflected.tsv
```

### Кастомный payload и маркер

```bash
./build/html-inject-scan -l urls.txt \
  -p '"><img src=x onerror=alert(1)>' \
  -m 'onerror=alert(1)'
```

### Авторизованная сессия

```bash
./build/html-inject-scan -l urls.txt \
  --cookie "PHPSESSID=abc123; BX_USER_ID=xyz" \
  --header "Authorization: Bearer eyJhbG..." \
  --auto
```

### Проксирование через Burp Suite

```bash
./build/html-inject-scan -l urls.txt --proxy http://127.0.0.1:8080 --auto
```

### Управление длиной запроса и параллелизмом

```bash
# Меньше запросов за счёт батчинга, до 8 URL параллельно
./build/html-inject-scan -l urls.txt --auto --max-url-len 4000 --threads 8
```

### Только находки (тихий режим)

```bash
./build/html-inject-scan -l urls.txt --auto -s
```

### POST-запросы

```bash
./build/html-inject-scan -u "https://target.com/api" --method POST --auto
```

## Все флаги

```
Targets:
  -u, --url <url>         один целевой URL
  -l, --list <file>       файл со списком URL (один на строку)

Injection:
  -p, --payload <str>     payload для подстановки (по умолчанию: '"><zxcasd>)
  -m, --marker <str>      подстрока для поиска в ответе (по умолчанию: <zxcasd>)

Parameter sources:
  -w, --wordlist <file>   файл со списком параметров (один на строку)
      --extra <a,b,c>     доп. параметры через запятую
      --no-extra          не использовать встроенный набор
      --mode <input|all>  режим HTML-скана (по умолчанию: input)
      --no-html-scan      не загружать страницу для парсинга name=

Session:
      --header <line>     заголовок 'Name: value' (можно несколько раз)
      --cookie <str>      cookie-строка 'k=v; k2=v2'
      --proxy <url>       HTTP-прокси, напр. http://127.0.0.1:8080
      --method <GET|POST> HTTP-метод (по умолчанию: GET)
      --timeout <ms>      таймаут запроса в мс (по умолчанию: 15000)

Scan behaviour:
      --auto              без интерактива: выбрать все найденные параметры
      --max-url-len <n>   макс. длина URL в батче (по умолчанию: 2000)
      --threads <n>       до N URL параллельно (нужен --auto, по умолчанию: 1)
  -s, --silent            печатать только находки
  -o, --output <file>     сохранить находки в TSV-файл
  -h, --help              показать справку
```

### Интерактивный выбор

Без `--auto` для каждого источника выводится пронумерованный список:

```
[URL query] Found 3 params:
  0  id
  1  type
  2  region
  a = all, n = none, e.g. 0,1,5-10 = pick by index
  >
```

- `a` или Enter — выбрать все
- `n` — пропустить источник
- `0,2` — выбрать по индексу
- `3-7` — диапазон

## Формат вывода

```
[*] Scanning https://target.com/page?id=1 (5 params, method=GET)
  [REFLECTED] coupon  200  https://target.com/page?coupon=%27%22%3E%3Czxcasd%3E
...
REFLECTED: 1 hit(s)
```

При `-o file.tsv` находки сохраняются в формате TSV: `param \t status \t url`.

## Архитектура

Код разбит на независимые, покрытые тестами модули в `src/`:

| Модуль | Ответственность |
|--------|-----------------|
| `url_utils` | разбор URL, query string, percent-кодирование, сборка URL с payload |
| `http_client` | класс `Session` поверх cpr: заголовки, cookie, прокси, GET/POST |
| `discovery` | сбор параметров из URL, HTML, словаря и встроенного набора |
| `selector` | интерактивный выбор параметров |
| `scanner` | батчинг под лимит длины, поиск отражающих параметров делением |
| `cli` | разбор аргументов командной строки |
| `report` | вывод в консоль (с цветом и тихим режимом) и сохранение в TSV |
| `parallel` | параллельное применение функции (`std::async`) |
| `main` | склейка всех модулей |

Все сообщения об ошибках реализованы через исключения и обрабатываются в `main`. Прямое
управление памятью не используется. Все используемые программой пути задаются пользователем,
абсолютные пути в коде отсутствуют.
